# Conversation Bridge

Chrome extension (Manifest V3) that captures AI conversations from ChatGPT, Claude, Gemini and Perplexity, keeps a local searchable library, exports clean Markdown / HTML / JSON / PDF, and hands context to another assistant with one click.

**No build step.** The folder is the extension: load it unpacked or zip it for the Chrome Web Store.

```
conversation-bridge-1.0.0/
├── manifest.json
├── sidepanel.html          side panel UI  (src/ui/app.js)
├── options.html            → opens the panel's Settings tab in a full tab
├── welcome.html            onboarding page shown once after install
├── print.html              print/PDF view
├── icons/                  generated by tools/make-icons.py
├── styles/panel.css
├── src/
│   ├── background.js       service worker: menus, commands, transfers, live sync
│   ├── content.js          runs on chat sites: DOM → Markdown, deep scan, composer insertion
│   ├── lib/                pure modules (storage, exporters, markdown, zip, importers…)
│   └── ui/                 side panel views
├── docs/                   privacy policy (store listing notes are kept out of the repo)
└── tools/                  icon generator, tests, packaging, marketing renders (not shipped)
```

## Develop

The same three checks run in GitHub Actions on every push and pull request (`.github/workflows/check.yml`), which also uploads the packaged zip as a build artifact.

```bash
npm run check        # syntax-check every JS file
npm test             # functional tests for the library modules (node tools/test-lib.mjs)
npm run test:dom     # DOM → Markdown regression test in headless Chrome (node tools/test-dom.mjs; --update to accept a new snapshot)
```

Load unpacked: `chrome://extensions` → Developer mode → *Load unpacked* → pick this folder.
After editing `content.js`, reload the extension **and** the chat tab.

Two fixtures help with UI work without loading the extension (serve the folder, e.g. `python -m http.server 8765`):

- `tools/fixtures/panel-dev.html` — the panel with a mocked `chrome.*` API and sample data. Add `?seed=demo` for a populated library (`tools/fixtures/demo-seed.js`); `?view=library`, `?open=<id|url>`, `?workspace=<id>&select=all` and `?collapse=1` deep-link into views
- `tools/fixtures/dom-test.html` — DOM → Markdown extraction against ChatGPT / Claude / Gemini-style markup

Debug hook on chat pages: in DevTools pick the *Conversation Bridge* context and run `__conversationBridge.extract()`.

## Features

Everything is free and unlocked — there is no paid tier, no license key and no account.

- Capture visible messages or the full thread (scrolls the page to load every message)
- Copy or export as Markdown, plain text, JSON, HTML or PDF; bulk export as ZIP
- Unlimited local library with search, tags, notes, favorites, pins and trash
- Transfer a chat to another assistant in one click
- Unlimited workflows, Overview / Working / Full context packets, related-chat suggestions
- Unlimited prompt templates
- Live sync of saved chats while their tab stays open
- YAML frontmatter and file-name templates for Obsidian / Logseq
- Backup / restore, and import of official ChatGPT and Claude data exports

## Known limitations

- Images in ChatGPT and Claude replies are served from signed, expiring URLs. Exports link to them rather than embedding them, so those links stop working after a while.
- Site adapters depend on each chat site's markup. When a site changes its DOM, capture on that site can break until the adapter in `src/content.js` is updated — `npm run test:dom` and `tools/fixtures/dom-test.html` are the place to reproduce it.
- Keyboard shortcuts default to Alt/⌥+Shift+B / C / S. Chrome reserves Ctrl+Shift+B and Ctrl+Shift+C for itself, so those cannot be used as defaults; any shortcut can be changed at `chrome://extensions/shortcuts`.

## Publish

1. Bump `version` in `manifest.json` and `package.json`, and add a `CHANGELOG.md` entry.
2. `python tools/build-zip.py` → `dist/conversation-bridge-<version>.zip` (excludes `tools/`, docs sources, `package.json`).
3. Upload at the Chrome Web Store developer dashboard. The listing text and dashboard notes live in `docs/STORE_LISTING.md`, which is kept out of the repository; the privacy policy is `docs/privacy.html` (host it, e.g. on GitHub Pages, and link it in the dashboard).
4. Screenshots and the website hero: `python tools/make-marketing.py` renders `dist/marketing/` (1920×1080 hero + five 1280×800 Store shots) from the real panel via headless Chrome. Edit `SLIDES` in the script to change headlines; the frame is `tools/marketing/hero.html`.

Users upgrading from a 0.x release keep their data — `storage.migrate()` moves the old `conversationBridge.*` keys into the new schema on first run.

## Adding a platform

Add an adapter in `src/content.js` (`adapters` array): `matches(hostname)`, `turns()` returning `[{ el, role }]`, `contentRoot(el)`, `title()`. Then add the host to `manifest.json` (`host_permissions` + `content_scripts.matches`), `SUPPORTED_HOST` in `background.js`, and `PLATFORMS` in `src/lib/util.js`.

## Contributing

Bug reports and site-adapter fixes are welcome. Before opening a pull request run `npm run check`, `npm test` and `npm run test:dom`; if a change alters the captured Markdown, refresh the snapshot with `node tools/test-dom.mjs --update` and include it.
